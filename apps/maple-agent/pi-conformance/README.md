# Pi reference harness

This test-only flake executes TypeScript Pi `v1.0.4` at
`7c10bd4337495ee613f2224843ecdf349b80d1df`. It is separate from the Agent
product flake and does not add Node to the product toolchain.

The reference installs Pi's exact npm lockfile with `importNpmLock`,
hydrates the model catalog using its upstream SHA-256 pin, and executes
source modules through Pi's Vitest configuration. Dependency and catalog
downloads are fixed-output Nix fetches. No provider account is used.

From `apps/maple-agent`:

```sh
just pi-upstream-tests
just pi-corpus
just pi-corpus-check
```

These recipes are separate from `just ci`. Ordinary Rust checks never execute
Node. `pi-corpus` is the only recipe that replaces committed expected output;
it copies a successful recording from Nix, with no Rust-output blessing mode.

The flake provides these independently reproducible checks:

- `upstream-tests` collects every test in the agent, AI, and coding-agent
  packages, including skipped cases. It executes the selected reference
  suites. Inventory IDs retain describe chains, parameterized cases, duplicate
  suffixes, and source locations; files carry their SHA-256 hashes.
- `corpus` depends on the passing reference tests, records every supported
  scenario and function matrix twice, and requires byte-identical outputs.
  Each run uses a fixed clock and seeded randomness. Events and provider
  requests are snapshotted before upstream objects can mutate again.
- `checks.<system>.corpus-fresh` compares that result with the committed corpus.

The aggregate `spike` output also records the exact Node version and catalog
size. The committed inventory and execution results omit durations and sandbox
paths. Vitest's `list --json` omits skipped tests, so the inventory uses its
programmatic collector instead. At the pinned revision it collects 480 files
and 4,970 runtime test cases, including 910 skipped cases. These are inventory
counts, not claims that every case applies to the Rust selection or passed.

## Progress and integrity

`selection/manifest.json` maps the 81 selected upstream source files to Rust
modules. Its scripts support later upstream reviews. `coverage/upstream-map.toml`
accounts for every collected test, while `coverage/corpus-status.toml` records
scenario and function progress. Pending entries are intentionally visible and
do not establish conformance. A passing pending replay fails the gate so its
status cannot silently remain stale.

The Rust `pi-conformance` crate checks input and output hashes, the source pin,
test correspondence, dependency boundaries, and DSL structure. Only an
implemented interpreter can promote a scenario or function group to passing.
The skeleton starts with runtime tests and replays pending. The final port gate
requires zero pending entries and explicit owner approval for any behavioral
deviation in `coverage/deviations.toml`.

The model catalog is fetched only inside the reference derivation. The corpus
contains just the frozen records requested by tests. The product toolchain and
repository do not contain the full catalog.

Development validation currently focuses on macOS. A successful macOS build
does not establish Linux sandbox execution or Windows replay portability.

The corpus is generated by the reference recorder. Do not edit generated
records by hand. Pi's MIT license is reproduced in `LICENSE`.
